### License chain

hunspell-vi has no LICENSE file of its own. Its README states it derives from the GNU Aspell
Vietnamese package, which in turn derives from Hồ Ngọc Đức's word list:

1. **Hồ Ngọc Đức, Viet39K.txt** (Free Vietnamese Dictionary Project): "The word list is
   distributed under GNU General Public License. If you modify it, please send me the
   modifications." — no version stated. Under GPL section 9 ("If the Program does not specify a
   version number ... you may choose any version ever published"), this is usable under GPL-3.0.
   Verbatim notice: `sources/hunspell-vi/Copyright-aspell6-vi`.
2. **aspell6-vi 0.01.1-1** (2004, packaged by Kevin Atkinson/László Németh): README says
   "Copyright Terms: GPLv2". This is the packager's statement about the package; the word list
   itself carries the unversioned notice above.
3. **hunspell-vi** (László Németh conversion; corrections by Ivan Garcia and Minh Nguyễn):
   modifications distributed under the same GPL terms.

**Assessment:** compatible with LanKey's GPL-3.0-or-later. Residual risk: if the aspell6-vi
"GPLv2" statement were read as GPLv2-only for the *corrections* layer, the combined list would be
GPLv2-only and not combinable into a GPLv3 binary. Mitigation options if that ever matters:
(a) ask 1ec5/hunspell-vi maintainers for an explicit "GPLv2 or later"; (b) regenerate the list
from phonotactic rules + a CC0/MIT corpus and diff against this one.

### Filtering applied (see `build_syllables.py`)

- Drop all-caps entries (abbreviations: `HTML`, `UBND`, `TCVN` ... 21 entries).
- Drop explicit loanwords (`web`, `internet`, `intranet`, `unicode`, `telex`, `tp`).
- Drop anything with a non-Vietnamese letter (f, j, w, z, digits, punctuation).
- Drop anything without a vowel (`v`).
- Lowercase proper nouns (`Huế` → `huế`, `Nguyễn` → `nguyễn`) — the syllable is valid.
- NFC-normalise (source is already NFC; kept as a guard).

Result on 2026-09-15: 6,711 raw → **6,683** syllables. 

### Known gaps (for Phase 2)

- No phonotactic cross-check yet: the list contains whatever the dictionary contains, e.g. `tẽ`
  is present (both OpenKey and VKey also accept it). A rule-based generator as a second source
  would let us flag dictionary entries that violate phonotactics and vice versa.
- Rare/dialect syllables missing from hunspell-vi will be flagged by AutoCorrect as typos until
  the user types them `kTrustMinFrequency` times. Track false positives during dogfood and add a
  `sources/lankey-additions.txt` overlay if needed.
